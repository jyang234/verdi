## Judged

- **judged-enumeration-completeness** [accepted-deviation]: ac-1 headlines 'every current disclosure for the checkout' and the spec's problem statement explicitly counts gate's disclosed conditions among the surfaces the operator must mentally union, but disclosureview.Current enumerates only the lint engine's disclosure-severity findings plus the serving process's startup extras — gate-derived disclosed states (gate:evidence-quarantine, gate:evidence-unprovable, gate:pending-supersession), which are computed from the checkout's current spec-store and evidence state, never appear in either edition, so the view's 'No current disclosures' empty-state claim can be a false total for a checkout whose gate conditions currently disclose (confidence 0.55) — Accepted as a spec-visible scope boundary, not silent narrowing: ac-1 scopes the enumeration to disclosures reachable 'through the internal/disclosure seam, computed fresh per render' — the lint sweep's disclosure-severity findings plus the serving process's startup extras, which are ambient checkout state recomputable per render. Gate-derived disclosed conditions are per-invocation outputs parameterized by a target ref: enumerating them would mean running every possible gate inside the view, a different mechanism than the seam render ac-1 names. The gap is real for an operator equating the panel with 'all disclosures anywhere'; the named, reversible follow-up is the spike's machine-enumerable channel (this spec's own oq-1, list_disclosures) where per-target gate disclosures naturally belong.
- **judged-dex-main-only** [accepted-deviation]: the spec's outcome commits the dex to the 'read-only, main-only edition' law, but internal/dex/disclosures.go enumerates from the local checkout root — including the never-committed mutable zone — so a locally built dex disclosures page is not a pure function of main's tree; the divergence is disclosed in a package comment and 'recorded in the round-5 divergence log' rather than declared in this spec, which is exactly the kind of intent drift the mechanical boundary diff cannot see (confidence 0.40) — Accepted as an already-recorded divergence, not new drift: the enumeration being a function of the checkout (including the never-committed mutable zone) rather than of main's tree alone is disclosed in the package doc and recorded in the round-5 divergence log — the ratified home for cross-spec divergences — and in the dex's CI home (a bare pipeline clone) that input is fixed, so published sites remain deterministic. A local build honestly reflecting the local checkout is the disclosed behavior, not a silent impurity. Reversible by a spec amendment restating the main-only law if the owner wants it binding over the divergence-log ruling.
- **judged-stable-id-rendering** [accepted-deviation]: ac-2 requires each enumerated item to carry the seam's fields — source, text, severity, stable id — in one consistent rendering, but the shared markup renders severity, source, scope, and text as visible content while the stable id survives only as a data-disclosure-id attribute; an operator reading either edition cannot see or cite the stable id without DOM inspection, so the id is carried by the DOM but arguably not by the rendering (confidence 0.30) — Accepted on ac-2's own verb: each item CARRIES the stable id, uniformly, as the data-disclosure-id attribute — the machine-citable channel the behavioral exercisers assert — while the visible text shows the human reading fields (severity, source, scope, text) in one consistent rendering. Surfacing the id as visible text is a reversible presentation follow-up, not a missing field: no item lacks the id and no edition renders it differently.
