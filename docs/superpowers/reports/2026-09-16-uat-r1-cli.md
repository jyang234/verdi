### Design choice

The witness is a real gate, not an obstacle: a verb dispatched before the
`verbPhase[verb]` lookup escapes `cliVerbs`' enumeration, so it ships
invisible to the whole showcase-coverage gate. `help` and `version` were
exactly that — real, shipped CLI capabilities that no enumeration named.
The fix makes the enumeration HONEST rather than widening the witness:

- `prePhaseSpellings` (enumeration_completeness_test.go) declares each
  pre-phase verb and the exact literal tokens it may be dispatched on:
  `lint`, `help` (help/--help/-h), `version` (version/--version). A flag
  spelling is the same capability, not a second one.
- `cliVerbs` hand-appends exactly those keys, so both are enumerated
  capabilities `showcaseCoverage` must map — ONE shared list, so the
  witness and the enumeration cannot drift in either direction.
- Default-deny is preserved, not loosened to "any `if` on verb": a
  blessed arm must have no init, no else, a body that never mentions
  `verb`, and a condition resolving to exactly one declared verb's
  spelling set. The one blessed helper condition, `isHelpToken(verb)`, is
  PINNED to its own source in help.go — blessing a helper call without
  pinning it would reopen the "a helper can hide an arbitrary predicate"
  hole the witness exists to close.
- `dispatch.go`'s lint arm now calls `verbUsageOrFallback("lint")`, not
  `(verb)`, restoring the verb-free body. No behavior change.

Rejected: adding `help`/`version` to `verbPhase` (changes the ratified
CLI-verb inventory `internal/specalign` pins) and any form of evading the
witness. `verbPhase` and the compact `usage` const are byte-unchanged.

`cli:help`/`cli:version` are then backed by real evidence, not a hollow
mapping (TestCLIShowcaseHelp/TestCLIShowcaseVersion). Help reads no
store, so the real corpus is what makes the NON-output provable: `verdi
spec --help` is compared against a real `verdi spec state
spec/stale-decline` projection over the same provisioned store, and
`verdi lint --help` against the real verb's own environment-dependence
(exit 0 in-store, exit 2 store-less) — the help spellings must answer
identically in both, possible only if lint's store-resolving entry point
was never reached. DISCLOSED: the obvious lint-output A/B is NOT
available — this store lints silently (clean corpus, mutable zone
present, so VL-017 does not fire), and the first draft of the test failed
on exactly that, so the silence is now asserted as a premise rather than
assumed, and the test can never pass vacuously. Version's expectation is
read back from the binary under test via `debug/buildinfo`, never a
hardcoded version string.

## Contract implemented

- ac-1 (CLI part): `internal/buildinfo.Line()` derives module version +
  short (12-char) VCS revision + `modified` marker from
  `runtime/debug.ReadBuildInfo`, falling back to the honest placeholder
  `verdi (devel)` when build info is unavailable or version is empty —
  never fabricated. `verdi version` / `verdi --version` (version.go) print
  it to stdout, exit 0, dispatched as top-level tokens in `run()` before
  the verb-phase lookup (never added to `verbPhase`, so
  `internal/specalign`'s CLI-verb inventory is untouched). `verdi serve`
  prints the identical line once, as its first stdout line, before the
  existing MCP-socket/workbench lines (serve.go).
- ac-2: central intercept in `dispatch.go`'s `run()`. `help`/`--help`/`-h`
  at top level print a new, richer `topLevelUsage` (one line per verb with
  a short description) to stdout, exit 0 — the existing compact `usage`
  const is untouched (still the no-args/unknown-verb stderr/exit-2 path,
  co-2). The same three tokens immediately after any known verb print that
  verb's `verbUsage` registry entry (one line per subverb/form) to stdout,
  exit 0, *before* the verb's real function is ever called — fixing both
  named defects: `verdi lint --help` no longer runs a lint, and
  `verdi spec --help` is now the clean stdout/exit-0 path instead of the
  usage-error stderr/exit-2 path. `designVerbUsage` was reformatted
  in-place to multi-line (contract-permitted); all 11 forms preserved
  byte-for-byte, only " | " became newlines. Every other `verbUsage`
  entry reuses an existing ratified constant (`obligationVerbUsage`,
  `waiveUsage`, `experimentUsage`) or is a fresh literal grounded in that
  verb's real argument-shape check.

Review-fix additions to the same contract: `verbUsage["help"]`/`["version"]`
plus matching branches in `dispatch.go` so "verdi version --help" and
"verdi help help" (and every three-spelling combination of each) show
that row's own usage rather than the version report or a second
top-level dump; `designVerbUsage` gained the real `--from-stub <feature>
<stub>` form it had omitted; `verbUsage["disposition"]` is now a clean,
