## Contract implemented

1. ac-1 footer. Every workbench page renders `internal/buildinfo.Line()` in
   a `<footer class="site-foot" data-testid="build-footer">` as
   `<p class="ritual-note">Build <code data-testid="build-identification">…</code></p>`.
   Defined once (`buildIdentificationFooter`, layout.go), injected via a
   template FuncMap into all four shells that render their own `<html>`
   (read-page shell, v0 board, v1 board, diagram editor). Styling: the
   existing `.ritual-note` muted note and `code` chip (`--mono`), plus ONE
   new rule `footer.site-foot` (top border on `--rule`, `margin-top:
   2.5rem`, `padding-top: 0.8rem`, mirroring `.site-head`) admitted after
   minor 1 found the class undefined. Body size, no `<small>` (minor 2):
   the muted colour is the only de-emphasis, so the line stays readable
   and pasteable. This worktree's line is `verdi (devel)` (observed via
   `go run ./cmd/verdi version`, exit 0), honest per dc-8; the Go test
   asserts the element carries exactly `buildinfo.Line()`.
2. ac-4 record page. "Verified import" gains `Format` (`record-format`)
   and `Profile primary digest` (`record-profile-primary-digest`) after
   `Request digest`, via `fact` generalised to `factWithID`. Format empty
   → both `not recorded (pre-ac-4 record)`; digest present → the digest;
   otherwise `not applicable`. Never blank.
3. R-5 policy guide. `asdShell.PolicyCode` carries the failure Code from
   both `policy-forbidden` branches; the guide renders `code + ": " +
   detail` (bare detail when code is empty). `PolicyDetail` stays bare, so
   the `strings.Contains(..., policyNotAdoptedDetail)` discriminant still
   matches; existing verbatim-detail tests pass unchanged.
