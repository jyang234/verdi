## Contract implemented

1. ac-1 footer. Every workbench page renders `internal/buildinfo.Line()` in
   a `<footer class="site-foot" data-testid="build-footer">` as
   `<p class="ritual-note"><small>Build <code data-testid="build-identification">…</code></small></p>`.
   Defined once (`buildIdentificationFooter`, layout.go) and injected via a
   template FuncMap into all four shells that each render their own
   `<html>` (shared read-page shell, v0 board, v1 board, diagram editor).
   Styling reuses only existing stylesheet classes (`.ritual-note` muted
   note, the shared `code` chip in `--mono`); no CSS added (the stylesheet
   is internal/dex's, outside this lane's write set). From this worktree
   the line reads `verdi (devel)` (observed: `go run ./cmd/verdi version`
   → `verdi (devel)`, exit 0), honest per dc-8; the Go test asserts the
   element carries exactly `buildinfo.Line()`, not a specific version.
2. ac-4 record page. `renderSpecImportRecord`'s "Verified import" block
   gains `Format` (`data-testid="record-format"`) and `Profile primary
   digest` (`record-profile-primary-digest`) after `Request digest`, via
   the existing `fact` helper generalised to `factWithID`. Values: Format
   empty → both rows `not recorded (pre-ac-4 record)`; digest present →
   the digest; otherwise `not applicable`. Never blank.
3. R-5 policy guide. `asdShell.PolicyCode` carries the failure's Code from
   the two `policy-forbidden` branches; the guide renders
   `code + ": " + detail` (bare detail when code is empty, never a dangling
   separator). `PolicyDetail` is unchanged and bare, so the
   `strings.Contains(..., policyNotAdoptedDetail)` discriminant at
   boardspecasd.go still matches; the existing verbatim-detail tests pass
   unchanged.
