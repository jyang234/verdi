## Contract implemented

1. **Both commit sites stage exactly the scaffolded spec directory by path.**
   `design.go:432` already binds `specDir := store.ActiveSpecDir(root, name)`
   before any write; the commit step now passes that same `specDir` to
   `gitx.AddPaths(ctx, root, specDir)` (design.go, was line 609; now inside
   the block starting at the old line number with an added doc comment).
   `designsupersede.go:204` binds the identical `specDir := store.ActiveSpecDir(root, newName)`
   before the checkout switch; its commit step (was line 257) makes the
   same swap. In both functions the ONLY file written to disk before the
   commit is `specDir/spec.md` (via `atomicfile.Write`), so staging the
   directory and staging that one file are equivalent today; the directory
   form is used because it's what the contract asked for and is
   future-proof if the scaffold ever grows a second file inside `specDir`.
   Verified by `gitx.DiffNameStatus(base, head)` in both new tests: exactly
   one changed path, `.verdi/specs/active/<name>/spec.md`.
2. **`regenerateBaseline` — confirmed no impact, behavior unchanged.**
   In both functions `regenerateBaseline(...)` is called strictly AFTER
   `gitx.CreateCommit` returns (`design.go`: `CreateCommit` then
   `regenerateBaseline` two statements later; `designsupersede.go`: same
   order). `regenerateBaseline` (`cmd/verdi/baseline.go:71`) writes to
   `.verdi/data/derived/<slug>/<commit>/`, a `.verdi/data/` path — CLAUDE.md:
   "Nothing under `.verdi/data/` is ever committed." Since it runs after the
   one-and-only commit in each function, its output could never have been
   part of that commit's tree under EITHER `AddAll` or `AddPaths` — the
   files don't exist on disk yet when the commit is made, under both the old
   and new code. There was no "later AddAll" relying on catching these
   files; nothing to change, nothing regressed. Not modified.
3. **By-path helper: pre-existing, reused verbatim, not new.**
   `gitx.AddPaths` already exists at `internal/gitx/addpaths.go:27` (added
   for D6-33 — accept.go's identical class of fix) with full test coverage
   in `internal/gitx/addpaths_test.go`: `TestAddPathsCommit_Happy`,
   `TestAddPathsCommit_MultiplePaths`, `TestAddPaths_PathspecsResolveAgainstDir`
   (3 subtests), and `TestAddPaths_Negative` (3 subtests: no paths given;
   not a repo; nonexistent path and not a deletion). This already satisfies
   the dispatch's "give it happy and negative tests (nonexistent path →
   error; path outside the repo → error)" — no new test needed, and none
   added. `internal/gitx/commit.go` (which only holds `AddAll` and
   `CreateCommit`) was read but not edited.
4. **Established mechanism mirrored, not reinvented.** `cmd/verdi/acceptdiagram.go:167`
   (`gitx.AddPaths(ctx, root, diagPath)`, a single file) and
   `cmd/verdi/close.go` (`stageClosureSpec`, `closeAddPaths(ctx, root, paths...)`,

   sites use the same `gitx.AddPaths` seam, no second staging mechanism.
