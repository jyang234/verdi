# UAT-034 — commit-to-design stages only its own spec directory

## Status

PROVEN. `internal/commitdesign.Run`'s scaffold-commit step now stages
exactly the spec directory it writes (`specDir` — `spec.md` and
`board.json`) via `gitx.AddPaths`, never `gitx.AddAll`'s `git add -A`. Both
production call sites into this ritual (`cmd/verdi/board.go`'s `board
commit` CLI verb and `internal/workbench/board.go`'s HTTP
`boardCommitHandler`) call `commitdesign.Run` directly with no other git
operation of their own around it, so the one-line fix inside `Run` covers
both entry points; `cmd/verdi/forgeboot.go`'s only relationship to this
package is a doc-comment cross-reference for its shared
`resolveModelDigest` helper — it constructs no `Input` and performs no git
operation itself. Read end to end, `Run` writes exactly two tracked files
before the commit (`specPath` = `specDir/spec.md`, `boardSnapshotPath` =
`specDir/board.json`) plus `boardio.GraduateStickies`, which writes to
`.verdi/data/mutable/annotations` — excluded from git by
`.verdi/.gitignore`'s `data/` pattern (confirmed identical between the
package's own fixture and the real repo's own `.verdi/.gitignore`), so it
was never part of the ritual's own tracked write set. No other tracked
write exists anywhere in the function.
