## 3. Operation and relation coverage

For each row below, request and result body fields, enums, requiredness,
nullability, ordering, canonical embedded bytes, and existing validators are
preserved by reference to Bridge §3.3 at its fixed publication base plus the
two ratified exceptions. `req/res` names the exact public arm versions.
Proposal §2 defines the sole schema transformation on the transport.

The relation column inventories the Verdi bridge/client relations at the
inspected source head. It is not permission to omit nested validators, later
completion checks, or ATC owner policy. “No extra relation” means the exhaustive
`crossMatchOwnerResult` branch has no request/result comparison for that
operation; it does not mean the owner can return an unchecked answer.

## 4. Coverage and limitations

Accounting totals: **23/23 named amendment units mapped; 12/12 retained-source
groups mapped; 22/22 public requests and 22/22 public results mapped, plus
1/1 local claims operation**. Transformations are named in §1; no preserved
arm field or owner responsibility is intentionally omitted.

This is amendment-scope accounting. It does not claim clause-level promotion
of every upstream specification, nor a completed function-by-function validator
migration. Entire retained sources remain authoritative at their locations.
If future work replaces those sources with a canonical consolidated contract,
it must provide the full clause-level losslessness witness first. The runtime
validator migration must separately provide the check-to-function/test witness
required by proposal §3 before any validation code is removed.

Known unproven work: v2 codecs, new negotiation ordering, process-crash matrix,
two-way store replay, performance measurements, and codec deletion. This document
records a design and implementation obligations, not successful tests.
