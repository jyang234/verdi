Fix round 1 (review finding F1, F4, F7): this file replaces the original
oq-3 blast-radius measurement. The original mixed a standalone
`go test ./internal/policyartifact/...` run with a full `go test ./...`
run in one log and then double-counted package-summary lines
(`grep '^FAIL'` matches BOTH a package's bare trailing "FAIL" line and its
"FAIL<tab>pkg<tab>time" line, ~2 lines per failing package) — the
independent review (lane-self-governance-review.md F1) caught this: its
own re-derivation in a fresh clone measured 479 cases / 19 packages,
against the double-counted 41 this file originally reported. This
version corrects the METHOD (an anchored, single-clone `go test ./...`
run; one command per number, run beside it) and reports THIS fix round's
own two independent re-derivations, which agree with each other (480/20)
but not exactly with the review's single run (479/19); the residual is
disclosed below, not silently resolved either way.

## Setup (repeated exactly as the original spike did)

  rm -rf /tmp/sg-fix-rung
  git clone -q --no-hardlinks <lane worktree> /tmp/sg-fix-rung
  cd /tmp/sg-fix-rung && git apply <path-to-committed>/oq3-rung-field.patch

## The full run

  cd /tmp/sg-fix-rung && go test ./... > testall.log 2>&1 ; echo "exit:$?"

exit:1 (this run and a second, independent fresh-clone repeat both gave
exit 1, and both produced the SAME 480/20/976 figures below — reported
in full un-reduced form once as evidence/oq3-testall-summary.txt, the
per-package ok/FAIL lines only, 101 lines).

## Reconciling 480/20 (this fix round, twice) against the review's 479/19

Both of this fix round's independent fresh-clone `go test ./...` runs
(one for this file, one bare re-run of internal/sealedexec/claude alone
to check for flakiness — it failed identically both times, same 9.9s and
4.2s-ish wall time, same message) gave 480/20. The independent review's
own single fresh-clone run gave 479/19 (lane-self-governance-review.md
row 4). Neither figure is fabricated; both are commanded and reproducible
in their own hands. The one-count, one-package gap is most consistent
with run-to-run variance in a large suite under this session's
documented, heavily fluctuating shared load (evidence/oq1-adoption/
timing.txt shows load averages swinging between ~2 and ~47 across this
session) acting on internal/sealedexec/claude specifically — the one
failing package whose own test spawns a real `go test ./cmd/verdi`
subprocess rather than running in-process, making it the most
load/timing-sensitive of the 19-or-20. This spike reports both figures
with their provenance rather than silently picking one; the
RECOMMENDATION is unaffected either way (a blast radius in the high
hundreds of cases across ~20 packages, not ~5).

    => 34    (a NAMED SUBSET of shape 2, called out on its own because

  grep -cE 'authority-invalid: resolving effective policy|"code":"authority-invalid"' testall.log
