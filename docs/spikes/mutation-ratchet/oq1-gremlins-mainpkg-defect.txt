oq-1 evidence (fix round 1): gremlins v0.6.0 reports a FALSE 100% kill rate
for every `package main` directory, and counts non-test errors as kills.

Root-caused with an instrumented `go` wrapper, gremlins' own source, and a
like-for-like counterfactual. Every run below happened in a throwaway local
clone of the scratch worktree, /tmp/fix-mr, `git clone -q --no-hardlinks
<scratch> /tmp/fix-mr && git -C /tmp/fix-mr checkout --detach e963f4d0`,
never in any worktree. Binary: /tmp/fix-mr-bin/gremlins, installed
`GOBIN=/tmp/fix-mr-bin go install github.com/go-gremlins/gremlins/cmd/
gremlins@v0.6.0` (exit 0; `gremlins --version` -> "gremlins version dev
darwin/arm64", the same `dev` string the lane already disclosed).
Toolchain: `go version go1.25.5 darwin/arm64`.

========================================================================

A wrapper named `go`, first on PATH, tees CWD, argv, exit status and the
head of combined output for every `go` invocation, then delegates to

same command with PATH=/tmp/fix-mr-shim:$PATH: identical verdict
("Killed: 354, Lived: 0 ... Test efficacy: 100.00%"), 356 `go`

========================================================================
3. Root cause in gremlins' own source
========================================================================

(a) The wrong package path.
$GOMODCACHE/github.com/go-gremlins/gremlins@v0.6.0/internal/engine/
engine.go:160-180, verbatim:

  func (mu *Engine) pkgName(fileName, fPkg string) string {
  	var pkg string
  	fn := fmt.Sprintf("%s/%s", mu.module.CallingDir, fileName)
  	p := filepath.Dir(fn)
  	for {
  		if strings.HasSuffix(p, fPkg) {
  			pkg = fmt.Sprintf("%s/%s", mu.module.Name, p)

  			break
  		}
  		d := filepath.Dir(p)
  		if d == p {
  			pkg = mu.module.Name

  			break
  		}
  		p = d
  	}

  	return normalisePkgPath(pkg)
  }

`fPkg` is the Go PACKAGE CLAUSE identifier, taken from the parsed AST
(engine.go:146 `pkg := mu.pkgName(fileName, file.Name.Name)`). The
function walks the directory path upward looking for a component that
ends with that identifier. For `cmd/e2eharness/readinessallproven.go`,
whose clause is `package main`:

  p = "cmd/e2eharness"  -> HasSuffix(..., "main")? no
  p = "cmd"             -> HasSuffix(..., "main")? no
  p = "."               -> HasSuffix(..., "main")? no; Dir(".") == "." ->
                           pkg = mu.module.Name = "github.com/jyang234/verdi"

So the import path collapses to the bare module path for every `package
main` directory whose basename is not literally "main". It is not a
timeout, a load artefact, or a build-tag problem: it is a deterministic
path-derivation defect.

(b) Why the failure is scored as a kill.
internal/engine/executor.go:193-217 and :257-266, verbatim:

  	rel, err := run(cmd)
  	defer rel()

  	if errors.Is(ctx.Err(), context.DeadlineExceeded) {
  		return mutator.TimedOut
  	}
  	var exitErr *exec.ExitError
  	if errors.As(err, &exitErr) {
  		return getTestFailedStatus(exitErr.ExitCode())
  	}

  	return mutator.Lived

  func getTestFailedStatus(exitCode int) mutator.Status {
  	switch exitCode {
  	case 1:
  		return mutator.Killed
  	case 2:
  		return mutator.NotViable
  	default:
  		return mutator.Lived
  	}
  }

gremlins expects exit code 2 to mean "this mutant does not compile"
(NOT VIABLE). On Go 1.25.5 that distinction does not exist. Measured
directly in a three-file scratch module (/tmp/fix-mr-exitprobe):

  build failure    -> `go test ./...` rc=1
  test failure     -> `go test ./...` rc=1
  missing package  -> `go test example.com/nope` rc=1

Exit 1 for all three, so `getTestFailedStatus` maps EVERY non-test error
onto KILLED and `NOT VIABLE` is unreachable on this toolchain. Every
gremlins report this spike produced says "Not viable: 0"; that zero is a
property of the tool on Go 1.25, not of the mutants.

========================================================================

  $ cd /tmp/fix-mr && go list -f '{{.ImportPath}} {{.Name}} {{.Dir}}' ./... \
      | awk '{n=split($3,a,"/"); if (a[n] != $2) print}'

3 of the module's 105 packages are silently unmeasurable by gremlins
v0.6.0. Two of them, `cmd/e2eharness` and `cmd/verdi`, are in the wave-1
touched set (9 of the 33 touched files live in them). No other package in
this module has a clause name that differs from its directory basename,
so the rest of the touched set is unaffected — but the general rule is
"directory basename must end with the package clause identifier", not
"must not be main": a hypothetical `internal/foo/bar` declaring `package
foo` would resolve upward to `.../internal/foo` and mutate one package
while testing another, equally silently.

CROSS_BINARY_PKGS cross-check (Makefile:32). Of that list, only
`cmd/e2eharness` is a main package, and it is the only member this defect
hits. The others (`internal/showcasealign`, `internal/specalign`,
`internal/experimentapp`, `internal/designapp`, `internal/sealedexec/
claude`, `internal/publicrelease`) all have matching basenames and run
correctly, as section 4's designapp control shows.

Separate but load-bearing for oq-1's own criterion: `cmd/e2eharness`'s
TESTS DO NOT build or exec the verdi binary. `buildBinary` (main.go:326,
`exec.CommandContext(ctx, "go", "build", "-o", out, "./cmd/verdi")`) is
called only from main.go:91, unprovenboard.go:146 and
specimportfixture.go:291 — all production paths driven by the harness
binary itself, none from a `_test.go`; `grep -rn "func TestMain"
cmd/e2eharness/` is empty. The genuine cross-binary witness in this
module is a package like `internal/designapp`, whose
`conformance_test.go:54` runs `exec.Command("go", "build", "-o", bin,
"github.com/jyang234/verdi/cmd/verdi")` from a test. That package is
section 4's control and gremlins handles it: it copies the whole module
root per worker (`workdir.NewCachedDealer(workDir, mod.Root)`,
cmd/unleash.go:179), so `./cmd/verdi` is present and buildable inside
each `wd-*`.


========================================================================
6. Mitigations tried and their cost
========================================================================

`gremlins unleash --help` exposes no knob for the package argument. The
complete flag list is -d/--dry-run, -S/--output-statuses, -t/--tags,
--coverpkg, -D/--diff, -o/--output, -i/--integration, -E/--exclude-files,
--threshold-efficacy, --threshold-mcover, --workers, --test-cpu,
--timeout-coefficient, and the eleven per-operator toggles. Of these:

  * `-i/--integration` IS a real mitigation, by accident. executor.go:
    199-201 and :234-237 replace both the cwd and the package argument in
    integration mode:
        cmd.Dir = m.mutant.Workdir()
        if m.integrationMode {
        	cmd.Dir = rootDir
        }
      ...
        path := pkg
        if m.integrationMode {
        	path = "./..."
        }
    so the broken `pkgName` result is never used. The cost is that every
    mutant runs the WHOLE module suite: at this module's 820s `make test`
    figure, 354 mutants at 2 workers is ~40 hours for one package. Not a
    gate option; recorded because it is the only in-tool knob that avoids
    the defect.
  * `-E/--exclude-files` scopes which FILES are mutated (and is the right
    answer to dc-2 — see oq2-evidence/exclude-files-scoping.txt), but it
    cannot repair the package argument for the files it keeps.
  * Excluding the three main packages from the mutation set entirely is
    the only configuration that is both correct and affordable. It costs
    coverage of 9 of the 33 wave-1 touched files.
  * A canary check is the only way to make the exclusion self-enforcing:
    before trusting any package's report, seed one mutant that MUST
    survive and assert the run reports it LIVED. Under this defect every
    package reports 100.00% efficacy, so "efficacy == 100%" is itself the
    alarm, not the goal.

Not tried: patching gremlins. Out of scope for a spike, and it would
break co-2's "pinned like golangci-lint" property unless the fork is
itself pinned and published.
